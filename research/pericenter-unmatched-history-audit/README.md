# Full-history check for unmatched pericenter values

The [prior three-snapshot audit](../pericenter-sampled-minimum/README.md) selected 1,977 events; 549 did not have a nearby proper-scaled separation numerically matching the catalog `d_peri` at tolerance 0.01. This exploratory follow-up searches every available, unique, valid snapshot 30–99 in those 549 orbit histories using the same nearest-image distance, scale factors and h=0.6774. The corrected merger catalog SHA-256 is checked, and the prior selection digest recorded. Reproduce with `python analyze.py /path/to/cluster_mergers.hdf5` using NumPy and h5py; it also needs the adjacent saved redshift table and prior CSV.

Exactly one of the 549 values matches a proper-scaled separation anywhere in its valid stored history under the same absolute numeric tolerance; none matches the minimum across its complete valid stored history. The median smallest numeric difference is 6.08. This does not establish why the other values differ: interpolation, a different pericenter convention, preprocessing, units, center corrections or unavailable samples remain possible. Searching a larger set also increases the chance of incidental matches. These are derived consistency checks on the same simulated catalog, not independent verification, a population estimate or evidence of a defect.

The [official field table](https://www.tng-project.org/data/cluster/) labels `d_peri` ckpc/h, and [Lee et al. (2024)](https://arxiv.org/html/2311.06340) describes a five-point quadratic fit near closest approach. The relation between this paper's method and the current corrected release remains unresolved. Continue to withhold interpretation of earlier fitted-comoving versus `d_peri` distance differences until the unit and construction are independently confirmed. Record the exact dataset version and sample filters in any request for clarification.
