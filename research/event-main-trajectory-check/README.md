# Repeated main histories matching one cached API observation

The input is the corrected, hash-pinned TNG-Cluster Cluster Mergers catalog and a minimized, previously retrieved official API observation for subhalo 0 at snapshot 99. It contains only the snapshot, subhalo ID, position and velocity; it does not include credentials or a full merger tree. See [official API field and tree definitions](https://www.tng-project.org/data/docs/api/) and the [catalog documentation](https://www.tng-project.org/data/cluster/).

For each event with exactly one snapshot-99 entry, compare the main history position and velocity to the cached subhalo observation, using maximum component differences <1 ckpc/h and <0.002 km/s. Nine event rows match (1, 2, 3, 4, 5, 6, 7, 8, 10); each has recorded `HaloID` 0. This is consistent with multiple events sharing a main trajectory and cautions against treating event rows as independent clusters. The tolerances reflect precision of the saved API response and are not physical error bars. Coordinate agreement is not a direct independent check of tree linkage, unique target identity, or membership in a present-day FoF group. It does not map the other recorded identifiers.

Run `python analyze.py /path/to/cluster_mergers.hdf5` with h5py and NumPy. `summary.json` records per-event residuals and hashes the cached observation. A fresh authenticated API response and its descendant/progenitor link are required before claiming a verified branch. Do not apply an assumed ID equality to the separate z=0 properties table. No observational, SIDM, or new physics claim is made.
