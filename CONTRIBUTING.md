# Make one claim reviewable

Start with a bounded question and a falsifiable prediction. Use a branch and PR for each research update; avoid rewriting historical numerical outputs in place.

Required materials:

- [Checkpoint](research/templates/checkpoint.md), hypothesis state, and explicit evidence labels.
- Primary source/version links and input provenance, rights, units, and hashes.
- Executable methods or an explicit missing-code boundary; dependency versions, seeds, output, tolerances, and limiting cases.
- Strongest conventional alternative, nearest blocker, and next useful test.
- Learning exercise or actual assessment, without implying mastery from generated text.

Separate public inputs from private/raw data. Never commit credentials, raw chats, unlicensed copied packages, or third-party likeness/branding. No paid compute, outreach, publication, or scheduler changes are implied by a research PR.

For the included audit, follow [reproducibility](docs/REPRODUCIBILITY.md). Historical code changes require a new run and a comparison rather than a silent replacement. Null results and failed retrievals are valuable records.
